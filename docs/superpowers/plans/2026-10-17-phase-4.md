# Phase 4 Implementation Plan

> **For agentic workers:** Execute inline using executing-plans. The user requested direct implementation. No delegation or commits: this workspace is not a Git repository.

**Goal:** Complete Phase 4 tasks 27, 67–68, 84–85, 87–91, 93–94, 98–99 in `task.md` as playable, persistent features.

**Architecture:** Preserve existing Phaser scenes and domain systems. Stage inventory mutations on an isolated InventorySystem before committing inventory and wallet together. Capture complete plain-data snapshots; validate and migrate before restore; save primary and backups in the same IndexedDB transaction. A serial save manager captures snapshots at queue execution, with debounced autosaves and explicit failure state. DOM controllers provide responsive slot, trade, crafting, pause and settings interfaces.

**Tech Stack:** Phaser 3.88.2, JavaScript ES modules, IndexedDB, Node assertion tests and browser integration checks.

## Task 3: Atomic IndexedDB and serial autosave

**Modify:** `src/persistence/SaveRepository.js`. **Create:** `src/persistence/SaveManager.js`, persistence integration tests.

- [ ] Test save slot isolation, backups, backup pruning, recovery consent, atomic failure, deletion isolation, preference persistence, fallback session mode, and retry after a failed queued write.
- [ ] `saveSlot` increments revision in the readwrite transaction, backs up only a valid previous snapshot, retains two backups per slot, and resolves only on `transaction.oncomplete`.
- [ ] `loadSlot` validates/migrates before returning; if only backup is valid, throw an error carrying recovery details until an explicit recovery request. Never silently replace a corrupt primary.
- [ ] `deleteSlot` deletes that slot and its backups in one transaction. Metadata and other slots remain intact.
- [ ] SaveManager serializes requests, captures state when each write runs, debounces gameplay changes, flushes on sleep/quest reward/manual save/exit, and leaves a visible retry state after failure.
